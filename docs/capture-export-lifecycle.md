# Capture export cancellation and deletion

Capture review now retains the active export task and an operation ticket. Leaving the review or confirming deletion invalidates the ticket, cancels the task and clears any prepared share file. Cancellation propagates to the detached ZIP worker. A completed worker must still match the current ticket and not be cancelled before publishing its share URL; otherwise its destination is removed. This closes the late-result path that previously could publish a ZIP after the review had been dismissed or the source deleted.

The ZIP exporter checks cancellation before inspection, between frames/payloads and before finalizing the central directory. Its existing failure cleanup removes partial output. Cancellation is cooperative: a currently running file read/write or integrity inspection may finish before the next check. This is not an instantaneous secure-erasure guarantee. A force-terminated process can leave a temporary file until the next launch. Startup cleanup now removes matching export files before new export workers can start; broader session retention remains unfinished.

Capture deletion now returns success. The review dismisses only after successful source removal; failure stays visible with its error. This pass-level action does not delete separate derived head/model reviews or externally shared copies. Full session deletion/ownership/retention acceptance is not established.

## Startup cleanup

`TemporaryExportCleanup` runs during `SessionStore` initialization. It removes only regular, non-symlink files directly in the app temporary directory matching `capture-<UUID>.zip` or `live-timing-<UUID>.json`. It does not recurse or touch capture folders, saved reviews, unrelated temporary files or externally shared copies. This also removes completed timing reports left by an interrupted process. Removal errors surface through the session store; cleanup is retried at the next launch. It is unlinking, not a secure-erasure claim.

Validation: all 118 core tests pass, including unrelated-name, directory and symlink preservation and idempotence. Both simulator and unsigned iPhone SDK builds pass. An installed simulator build was launched with two synthetic abandoned-export files and an unrelated sentinel in its actual current container. After launch, both exports were absent and the sentinel remained. The sentinel was then removed by the test driver. No participant files were used and no camera started. This tests startup recovery from leftover files; it does not simulate an OS kill at every possible write boundary.
