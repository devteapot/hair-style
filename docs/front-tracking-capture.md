# Front capture with retained head tracking

The milestone review identifies a central M1 dependency: current AVFoundation front captures retain synchronized RGB/depth but explicitly have no head pose. This forces image/depth registration across every turn. Increasing saved sampling density may reduce the difficulty, but does not supply an independent initialization.

The installed SDK exposes `ARFrame.capturedDepthData`, `capturedDepthDataTimestamp` and face anchors. An optional ARKit front-capture experiment can retain a tracker estimate alongside original depth. Raw-depth/image calibration, mirroring, timestamp skew, anchor continuity and actual saved rate must be checked on physical hardware before such an experiment replaces any existing path. A face tracker estimate is not measured skull geometry or accepted registration.

The capture contract now supports optional `HeadPoseEvidence`: a `headFromOpticalCamera` rigid transform, timestamp, anchor UUID and explicit `arkit_face_tracking` source. Validation requires a valid rigid transform, finite timestamp within 10 ms of the image timestamp, a valid UUID and agreement with `quality.headPoseAvailable`. Existing captures retain nil pose and unchanged semantics; older readers that reject pose claims must be updated to consume new pose-bearing frames.

The optional recorder is now implemented behind “Retain head tracking (experimental),” off by default. It runs an `ARFaceTrackingConfiguration` with one tracked face, retains raw converted float32 depth, original calibration and depth filtering state, actual depth timestamps, source pixel formats, and nominal AR camera rate. Sampling requests 3 or 15 saved frames/second; actual delivery still needs measurement. Existing AVFoundation capture remains the default.

The recorded optical-camera-to-face transform is `inverse(worldFromFace) * worldFromARCamera * diag(1,-1,-1,1)`. It is a tracker estimate at the RGB timestamp, not a reconstructed skull. Camera tracking must be normal, face tracking active, and depth within 10 ms of RGB; saved depth timestamps cannot repeat. An observed different tracked anchor interrupts the pass instead of joining identities. Five seconds without eligible synchronized tracked depth interrupts and preserves the partial capture. Capture validation also rejects pose/depth timestamp mismatch beyond 10 ms.

The unsigned iPhone SDK build passes. The 132 core tests include round-trip provenance and rejection of missing, mistimed or mislabeled pose evidence; this is contract evidence, not execution of ARKit hardware callbacks. No new phone build was installed or camera activated. Physical validation remains required for depth/RGB calibration, optical-axis alignment, mirroring, anchor continuity, tracking loss, timestamps, saved cadence and reconstruction improvement under unchanged acceptance gates. In particular, AVDepthData calibration and the ARKit camera frame must not be assumed interchangeable for geometric fusion until measured.

## Pose initialization and independent residuals

`capture-inspect tracked-register BUNDLE REQUEST.json OUTPUT.json` consumes two frames from one completed front capture. The request contains `sourceFrameID`, `targetFrameID`, and 3–200 uniquely named `validationPairs`, each with source and target image pixels. Both frames must retain matching anchor IDs, native unmirrored coordinates, synchronized depth and valid poses. Existing recordings without retained tracking are explicitly rejected; no pose is inferred or backfilled.

The initializer is `inverse(headFromTargetOptical) * headFromSourceOptical`. Independent selected image/depth landmarks are sampled through the existing calibrated depth path, and every residual, median and nearest-rank p95 is retained. Changing validation pixels cannot change the transform. The report binds the source/target stored frames and request by hash, records synthetic versus sensor provenance, and always has `acceptedForFusion: false`. It cannot replace an accepted captured-registration report or bypass existing fusion gates. Physical calibration and later registration refinement are still required.

All 135 core tests pass. New tests cover noncommuting rotation/translation direction, inverse round-trip, anchor mismatch, missing tracking, mirroring, timestamp mismatch, duplicate samples, payload corruption, and preservation of a large outlier without fitting to validation. An actual synthetic CLI run in ignored `outputs/tracked-registration-smoke/` produces the expected −10 mm translation and all three 10 mm residuals, with acceptance false. The unsigned iPhone SDK build passes. These checks establish implementation behavior only; no physical tracked recording is available yet.
