## Known limitations requiring implementation

1. Front capture has no automatic head-relative pose. Rear AR world pose does not compensate for subject movement. The surface builder requires explicit independently validated landmark registration; it does not substitute AR world poses for this step.
2. Selected registration rays use lens correction; the diagnostic point-cloud viewer is still pinhole-only. Full-image rectification and physical calibration validation remain. No precision claim is justified.
3. Sensor validity and supplied inclusion masks are enforced during surface building, but blur/exposure/coverage/motion gating remains. Offline face parsing has been evaluated; complete native occlusion handling is still missing.
4. Retention scheduling, subject/session switching, orphan recovery, and complete storage lifecycle need implementation before a study.
5. Pretrained Metal execution and model review are connected experimentally. Person-conditioned model generation, backend operation, research licenses and dependent asset terms remain unresolved.
6. No person-specific haircut is generated yet. A procedural baseline now supports constraint development, but cannot replace the specified AI/personalization evaluation.

Next engineering work: validate positive landmark detections/correspondences, implement automatic masks and head completion, refine overlapping surfaces, strengthen capture recovery, and establish a runnable strand-generation backend. Physical validation now has one front-face pass; proceed with timing exclusion, positive correspondence checks, a rear pass and a measured rigid fixture.
