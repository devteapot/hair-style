# Native durable processing lab

From the synthetic Guide studio, choose **Test durable processing**. This entry point accepts only synthetic fixtures; model/participant reviews do not expose it. Supply a service origin, then explicitly choose **Upload synthetic fixture**. The local-development default is loopback, which works with the simulator's host service; it is not a deployed phone backend.

The lab uses endpoint-scoped Keychain credentials and saves the source fixture, endpoint, request key, remote session/job IDs, actual stage/status and verified mesh to protected, backup-excluded application-support storage. The request key exists before submission, and the remote session ID is persisted before uploads. **Continue / refresh job** reuses the saved data/identities, resumes hash-bound uploads if necessary, queries actual job status, and downloads/replays a completed result. There are no invented progress percentages. An existing job with a missing Keychain credential reports an error instead of creating a different guest.

The verified mesh is cached with its immutable source. Relaunch revalidates that source and recompiles/hash-compares the cached mesh before display, without a network request. The viewer uses actual material radius; the two synthetic guide lines are correspondingly very thin. The screen and text were visually inspected. This is pipeline inspection, not hair-density rendering or personal styling.

Validation: the native simulator test ran through guest creation, upload, submission, one actual compiler invocation, verified download, display and app relaunch. A separate UI test then restored/displayed the cached result after the server and worker had been stopped. Both tests and the unsigned iPhone SDK build pass. Evidence remains in `outputs/native-processing/` with synthetic artifacts; no participant captures were uploaded.

The delete control first requests backend session deletion and then removes the local cached state; this UI action still needs a dedicated interruption/retry test. The original guide fixture is separate. The guest credential remains in Keychain because it may own other sessions. Network errors preserve the saved test. Session creation now sends the request key persisted before networking; a retry recovers the same owner-scoped session. Deletion retries acknowledge the existing tombstone, and reusing its creation key cannot resurrect it. Concurrent creation, legacy database migration and repeated HTTP create/delete are covered by 12 passing backend tests. The synthetic Swift HTTP probe also recreates its client, reuses the session/job, retries deletion and confirms resurrection is rejected, with exactly one compiler invocation. Native interruption timing and abandoned-session expiry remain unverified. Automatic polling, background transfers, native interrupted-upload testing, cached-state recovery and production endpoint setup remain unfinished. This screen is an engineering lab, not the consumer autonomous/guided generation flow, and it does not close the personal-head or personalized-generation gates.

## Cancellation

The lab exposes Cancel job after submission. It persists cancellation intent before contacting the service, then requests cancellation and reads actual status. Lost responses retain the intent; Continue / refresh or Retry cancellation repeats the idempotent request. A running worker remains visibly pending until acknowledgement. If completion won the race, the screen says so and permits retrieval of the completed result. Cancelled jobs and their source remain inspectable as metadata; session deletion is a separate action. Legacy saved records decode with optional state/intent fields.

Cancellation prevents publication but does not immediately kill an in-flight compiler subprocess. The worker checks between stages and at publication. A real-compiler test injects cancellation immediately before publication and verifies the generated result is removed, output hash remains absent and result access is rejected. All 13 backend tests pass, as does the iPhone SDK build. The native simulator test also passes: it submits to the actual loopback API with no worker, cancels the queued job, terminates/relaunches the app and verifies the cancelled status remains with no result view. The service was stopped after the test. Running-worker interruption and response-loss timing have not been exercised through the native UI.
