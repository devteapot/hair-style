`tools/probe_personal_latent_constraint.py` is a local one-guide experiment. It extracts the actual 64-dimensional latent of the seed-43 nape guide from a regenerated HAAR texture, verifies that pretrained decoding reproduces the recorded curve, and optimizes that latent through the frozen decoder against the existing inferred personal envelope. No decoder weight is trained, no curve point is directly projected, and no modified curve is labeled as unchanged upstream output. The root is held fixed by the decoding/mapping construction.

The objective penalizes continuous segment minima below the inferred envelope, along with changes in decoded geometry and latent values. Adam uses 200 steps at 0.005, with a fixed ±0.25 per-component latent trust region. The v2 objective includes both mean and maximum penetration penalties; v1 used only the mean. Both retain the same envelope target. These are experimental choices, not validated physical tolerances or a production optimizer.

## Evidence

- CPU decoding reproduces the selected source guide within 3.50e-7 template units. CPU and MPS gradients agree at the declared tolerance; maximum gradient difference is 1.44e-6 for v2. CPU fallback is disabled.
- Two hundred v2 optimization steps take about 1.03 seconds after loading/setup for this one guide. This is not full-hairstyle latency.
- Independent double-precision replay of saved mapped curves finds the minimum normalized radius improves from 0.97095727 to 0.98992897, but the required minimum remains 0.99523517. The constraint still fails. The mean-only variant also fails.
- The root is exactly unchanged. The maximum decoded point change is 9.124 mm; this is a newly decoded research candidate, not a permitted 2 mm import repair. It is not published as a canonical haircut.
- Fifty-three of 64 latent components reach the ±0.25 trust bound. The experiment does not justify enlarging that bound without evaluating distortion and model plausibility.

This shows a differentiable route for actual personal geometry to influence model decoding, beyond a global fitted asset or regional haircut policy. It does not establish a successful constraint solution, a whole hairstyle, aesthetic personalization or physical feasibility. Scalp anatomy remains inferred. The optimized curve has not been rechecked against the original template surface, and lengths, all-guide consistency, self-collision and renderer integration remain undone. Existing import limits are unchanged and both earlier whole-hair candidates remain rejected.

Reports and saved latents/curves are local under `outputs/personal-latent-probe/` and `outputs/personal-latent-probe-max/`. Source/texture/input/mapping/decoder hashes and the v2 script hash are retained. No participant upload, phone mutation or native/core source change occurred in this experiment.

## Bounded regional candidates and canonical replay

For each failing guide it considers up to 32 nearest latents from the same provisional region and four interpolation fractions, then decodes at that guide's own root/basis. It selects the lowest RMS point-change candidate satisfying the unchanged envelope plus a declared 20 mm maximum candidate point-change limit. This is a bounded new-candidate design search, not a larger import-repair allowance. It can change local curl/style coherence and needs visual/physical evaluation.

## Single-command local conditioning pipeline

`tools/run_prepared_personal_generation.py PREPARATION_DIR TEXTURE SOURCE SAMPLER_REPORT NEW_OUTPUT_DIR --preparation-output-sha256 HASH` now executes the existing research stages in order. Run it with the prepared Metal environment's Python. The preparation directory must retain `source-input.json`, `prepared-brief.json`, `mapping.json`, `anatomy.json` and `preparation-result.json`. The expected hash comes from the published preparation result.

The command snapshots bounded input files, independently consumes preparation before accessing model inputs, and runs full-field Metal optimization, regional search, canonical export/clearance, and actual-radius mesh compilation. All model stages set offline mode and disable CPU fallback. Each stage retains a log and outcome; the final report binds input files, export/clearance and mesh hashes. The mesh must match the reviewed haircut hash and use radius scale 1. Output always requires research review; this command neither accepts a haircut nor publishes to the native app.

The actual ready participant run completes in 61.123 seconds: preparation 2.91 s, optimization including setup 35.92 s, regional search including setup 12.28 s, export/clearance 8.36 s and mesh 1.35 s. These timings were measured while the separate CPU orientation search was running. It yields 763 guides and 230,426 vertices with the same 328 segment/24-guide clearance failures and two missing ear regions. Independent checks confirm byte-identical prepared inputs through all stages, exactly unchanged neural roots and a mesh matching the reviewed revision/file hash. A negative run using the original root-conflict preparation and deliberately nonexistent model paths fails at preparation without accessing those paths or creating optimization output.

The separate dense rotation search evaluates 616 orientations for each of the nine remaining v2 guides. It clears guides 655 and 656, leaving 128 segment intersections across seven guides and no root conflicts. Independent checks against the initial export confirm fixed roots and preserved curve shapes; neither newly changed guide had previously been rotated. Maximum total point movement is 19.96793 mm, within the unchanged 20 mm bound. The seven unresolved guides retain their geometry. Further resolution, missing anatomy and style/physical validation remain necessary.

Private pipeline output and independent verification are in `outputs/personal-conditioning-pipeline/`, the negative result in `outputs/personal-conditioning-pipeline-rejected/`, and dense-search output/invariants in `outputs/prepared-neural-export-v2/`. This is a local foreground conditioning pipeline for an existing model sample. New brief-driven sampling, durable worker integration and native launch/retrieval remain outstanding; the pipeline does not claim those capabilities.
